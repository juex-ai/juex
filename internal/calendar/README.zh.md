# Calendar

[English](README.md)

Calendar 拥有 Fleet 共享日程、执行历史、应用开关和通知 outbox。Management
解析用户及 Agent 权限；Runtime 将明确指定 Agent 的任务接纳为有预算的普通
Worker。纯提醒直接发送站内通知，不调用模型。类型化私有 SDK 位于 `rpc`，
用户和 Agent 入口不能自行提供任意执行身份。

PostgreSQL 适配器用短暂的单行锁串行修改每个 Fleet 的有界状态。规则修改、
occurrence 身份和 outbox 事实一同提交，网络请求在锁外执行。每个 Fleet 限制为
1,000 条日程、100 次未完成执行、50,000 条保留执行记录和 64 MiB 状态。达到容量
时拒绝新增，不丢弃未完成或结果未知的操作，也不阻塞其他 Fleet。

每次执行冻结目标、任务内容、日程版本和授权。规则修改和改派只影响未来派发。
派发先查询原 Runtime 回执，再决定是否接纳；响应丢失后沿用同一身份重试。
已经持久化的执行不受补跑期限影响。外部操作结果未知的 Worker 保留为待处理，
不会生成替代执行。模型结束和外部操作结束分别跟踪：已完成的 Worker 仍可能拥有
运行中的后台操作，Calendar 持续查询原身份，模型结束或应用停用后仍能取消。
取消保持请求状态，直到 Runtime 确认结束。并行派发尝试带版本隔离，旧响应不能
覆盖较新的结果。

故障恢复只选择尚未记录的最近一次触发，并检查该日程的补跑期限，默认 24 小时，
可配置为 1 至 1,440 分钟。超期记录为错过。人工暂停恢复、应用停用启用只安排未来
触发。应用停用时，有权限的人仍可只读查看，Agent 访问和新触发停止。目标或授权
失效后，日程暂停，须基于当前权限显式恢复。归档保留定义和历史；恢复定义后仍为暂停。

`recurrence` 只计算日期。固定间隔保留持久锚点。公历不存在的日期和夏令时跳过的
时间不触发；重复的当地时间仅在第一个时刻触发。农历依赖内部有可变缓存，因此
转换串行执行。向未来搜索限制为十年。农历单次日期在接纳时归一为绝对时刻。
本模块不读取用户本地文件系统，也不执行用户代码。

完成、提醒和待处理通知分别跟踪 Main 和站内通知的确认。Main 通知进入下一次输入
的上下文，不产生新唤醒。通知偏好和已验证邮箱投递归 Management 所有。

Agent 清理会暂停指向它的日程，保留共享定义和执行历史。阻止尚未派发的工作，外部效果不确定时明确保留未确认状态。新增和恢复日程在 Fleet 事务内检查目标的清理标记。整个 Fleet 清理则删除 Calendar 状态，并阻止迟到初始化。
