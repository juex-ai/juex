# Managed Runtime

> [English](README.md) | 中文

内置应用通过各自认证的 RPC 命名空间，将固定任务接纳为普通 Worker。任务身份、
首个输入和 Worker 用途原子提交；取消先到时只留下持久收据，不创建 Worker。
应用服务凭据不能提交普通输入、读取任意对话历史或控制其他应用的任务。
已接纳的应用工作独立于来源对话的取消。

应用 Worker 拒绝无关输入和创建子 Worker。Memory 审查 Worker 只提供自身上下文和
Memory 审查工具；工具派发和模型尝试接纳也检查这一限制。模型调用（包括未知结果的
尝试和压缩）使用普通调度器并消耗持久任务预算。每次调用和工具派发检查当前应用权限；
撤销会停止任务，恢复时不能自动取得新的执行代际。

Runtime 拥有 `runtime` PostgreSQL schema。Agent 是持久身份，Activation 是可替换的租约持有者。
Main 与 Workers 分别保存输入、历史、上下文代际和取消状态。调度器交错处理不同用户，限制活跃 Thread；空闲 Activation 不占用执行槽位。

创建 Worker、接受明确的首条任务及可选结果订阅，在调用工具的租约校验下原子提交；Worker 从独立上下文开始。
Agent 默认允许一层 Worker，可配置为两层，Turn 固定该策略。parent 只表达拓扑，不拥有取消权限：已接受的任务不因发送方停止而撤销。
同一 Agent 的结果订阅通过持久、受代际约束的收件箱投递有界的最终文本及 Turn 标识。重新订阅不重放旧结果；普通退订不撤销已接受的输入。
取消 Thread 会取消其已接受输入并禁用订阅。空闲 Worker 可以归档、恢复，历史保留且旧任务不重放；存在活跃子 Worker 时不能归档。

跨 Agent 协作只向同 Tenant、同所有者、同 Fleet 的其他 Agent Main 发送明确消息；管理员代管也不能越过此边界。
接受时检查双方权限，接受后由目标 Scope 和原始操作者控制执行；来源身份仅用于溯源，不构成持续依赖。
发现其他 Agent 只暴露名称和 ID，不开放私有对话或跨 Agent 的上下文引用。

`juex-runtime` 与 `juex-management` 独立运行。Management 通过 Kitex 转发会话请求，Runtime 通过 Management RPC 获取当前权限与模型凭据。
双向通信都要求部署 CA 签发的对应服务证书，CA 私钥只由运维保管。Runtime 不需要 Management 的加密密钥或数据库 schema。

输入回执和 request ID 去重在执行前提交。事件使用 Thread 内连续序号；重建上下文不读取 Workspace 文件。
Turn 固定指令和模型配置。每次新模型调用通过注入的业务接口重新检查当前权限与凭据可用性，Runtime 不查询 Management 表。

所有 Activation 写入都锁定并校验数据库租约；接管会增加 fencing 代际，过期实例不能发布回复。
恢复沿用原 Turn，将未确认的模型请求标为 unknown。Provider adapter 的一次网络请求对应一条持久 attempt；完整、部分和缺失用量分别记录。
模型请求的恢复规则不能作为重放外部工具操作的依据。

大段文本投影为明确标注的预览和限定作用域的 `read_context` 引用。原始消息仍保存在 PostgreSQL；字节分页保持 UTF-8 完整，不能跨 Thread 读取。
这个 Runtime 工具不依赖 Execution gateway；返回的页不会在游标后被静默截断。

Turn 固定有序且获授权的模型候选。回退只能向后选择预设候选，当前位置跨工具轮次和 Activation 恢复保留。
每次请求保存实际模型、上下文／输出限制与报告用量；失败响应不会执行工具。每个候选在调用 Provider 前重新接纳授权，超出候选容量时以明确原因暂停输入。
切换模型时，Provider 历史投影移除不兼容的推理签名与 ID，同时保留原始消息和工具配对。外部操作结果未知不会触发模型回退。

成员、代执行者和 Agent 执行代际防止撤销后恢复使旧队列工作复活。人工取消持久化且只影响该 Thread。
迟到的 Provider 用量可以结算已取消请求，但不能追加 Assistant 消息。服务关闭保留未完成工作以供恢复。

工具调用先持久化稳定操作 ID，再投递给 Execution。独立投递任务在环境离线时释放模型执行槽。
Execution 事实先进入去重的持久收件箱，再确认消费；晚提交的事件不会被序号游标漏掉。
结果在当前 Activation 租约校验下恢复原 Turn，保留配置与工具结果顺序。外部结果未知时阻塞 Thread，等待人工决策。

文件发布、Artifact 导入和明确的环境间复制，在接纳前固定来源与目标的已授权位置。
持久传输 ID 和完成事件恢复原工具调用，无需轮询模型。上下文只接收文件元数据和 Artifact 引用，不接收二进制内容。
省略位置只会选择托管工作区，不会改选其他设备。外部取消保持待确认，直到 Execution 确认原操作结束；
只接收取消请求不代表结束。取消先于已超时请求的迟到接纳时，会阻止该请求执行。

模型获得授权环境清单，只为文件、进程和 MCP 工具选择位置；句柄始终绑定原环境。
设备状态变化更新相关等待任务。独立观察器按持久字节游标读取 MCP 通知与进程输出，不占用 Activation，也不重新连接服务。
事件身份包含来源字节位置；相同内容在不同位置仍是不同事件。Main 接收有长度限制的摘要，默认不因此唤醒模型。
Thread 显式订阅后，匹配事件生成去重的输入并保留外部事件来源。设备状态投递比较当前状态，合并过时的 outbox 事实。
取消或替换订阅会阻止旧队列与迟到投递；每次唤醒重新检查原执行者、Agent 与设备授权。
Runtime 只有在解析后的事件和未完整解析的记录均已持久化后，才确认来源字节已消费。
取消 Thread 会补齐工具协议记录，并持久化外部取消投递，包含已完成 Turn 留下的活跃句柄。
已完成的会话历史与其他 Thread 保持不变；迟到结果不能重新启动它。

上下文压缩是原 Turn 内的持久 Runtime 任务，使用普通模型执行槽和固定的回退候选，但禁用工具并使用独立的摘要输出上限。
自动压缩保留当前输入、尚未消费的观察事件和近期完整工具往返；长 Turn 中较早的已结束工具批次可以进入摘要。
手动命令按 Thread 提交顺序排队，不作为用户聊天消息；较短上下文无需调用模型。

摘要通过校验后，在同一租约事务中提交检查点并推进 Thread 与 Turn 的上下文代际，原始历史仍可读取。
待处理任务跨重启保留源消息边界，后续排队输入和模型记账事件不会改变该边界。
无效、截断或没有释放足够空间的摘要保留原上下文并暂停输入；恢复尝试有持久次数上限。
独立后台进程、MCP 连接和观察订阅继续运行。

内置应用使用自己的 RPC 身份提交不可变结果摘要，摘要不会排队启动模型。
下一次已授权 Main Turn 消费有界批次，先核对原执行授权与应用代际／屏障，再追加系统动态。
已撤销的摘要跳过；应用暂时不可用时公平延后检查，不阻塞普通对话。
应用事实不能成为 Memory 的原始人类证据。

Runtime 在原状态变更的同一事务中冻结有界的完成、失败、输入暂停和操作结果未知通知。
应用 Worker 的最终结果仍由所属应用通知。明确的执行环境等待在持续 30 秒后成为通知候选，
也包括应用 Worker；发送前重新核对原 Tool、Turn、输入和取消状态。
查询暂时失败保留此前等待原因，不自行产生新的离线结论。outbox 重试冻结的身份和内容，
不占模型执行槽，也不创建输入。Management 管理个人站内通知、偏好和已验证邮箱投递。
通知链接原 Thread，不包含原始模型或 Provider 内容、工具参数或输出。
