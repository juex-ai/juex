# Management

> [English](README.md) | 中文

Management 拥有全局用户、租户、成员关系，以及用户在每个租户内的唯一 Fleet。登录凭据与稳定 User 身份分离。PostgreSQL adapter 拥有 `management` schema；其他服务通过业务接口调用，不直接写入这些表。App 负责数据库连接与组装。Management 不依赖以 Home 为基础的 Fleet 进程管理器。

已认证的 Management HTTP 服务和 Web 使用此目录。`CreateUser` 是身份创建原语，`CreateTenant` 是运维操作，两者都不是公开注册入口。适配器必须从已认证会话取得 actor ID。成员操作传入的角色是修改目标，不是调用者权限证明。

每个成员写入操作先锁定 Tenant 行，再读取当前权限并检查最后一位有效管理员。成员变更、actor/owner 审计事实与 outbox 在同一事务提交。成员版本保留停用／恢复的顺序。outbox 持久化只是意图记录，不证明下游取消完成；消费者不能因为新版本已恢复访问就丢弃先前的停用事件。

接受邀请要求登录匹配的账号，不会验证邮箱。令牌单次使用、有期限、以摘要保存，重新签发使旧令牌失效。已移除成员只能接受新邀请恢复，沿用保留的 Fleet。创建邀请时返回令牌原文；加密副本支持 Dashboard 持续展示复制链接，摘要不能还原邀请链接。

密码使用限制资源消耗的 Argon2id；人工登录会话与能力令牌保存摘要。受邀注册不能重置已有账号。初始化与运维恢复没有公开 HTTP 入口。密码恢复撤销人工登录会话，与设备凭据、Agent 执行独立。接受邀请不代表邮箱验证；SMTP 密码恢复要求通过独立流程验证邮箱。

邮件正文加密后与业务事务一起进入队列。发送器单独记录 SMTP 接收状态，不混淆邀请状态。重试沿用消息 ID；连接状态不明确时，SMTP 无法保证恰好一次投递。确认发送后清除队列中的能力链接正文。公开 API 响应不包含密码摘要、Provider 密钥或平台加密密钥。

`Fleet` 仅授权读取。有效租户管理员可以查看已移除或停用成员的保留数据；读取结果不授予配置修改或执行权。代管读取同时记录 actor 与 owner。执行及设备许可授权是独立操作。

Fleet 设置拥有默认模型配置。Memory 和 Calendar 各自拥有应用启用状态和执行代际；
Dashboard 通过经过认证的应用 API 读取和配置各服务，不维护重复开关。

模型由部署方提供。租户默认继承目录，也可使用显式允许列表；空列表不授予任何模型。Fleet 默认继承平台模型，Agent 可以覆盖；运维配置有序、不递归展开的回退列表。
快照接纳与每次凭据解析都在一个 Management 事务内检查当前资源权限。模型和租户访问代际防止撤销再恢复使旧 Turn 授权复活，未受影响的候选仍可用。
密钥轮换不改变已固定的路由；端点或协议改变后，旧路由快照不能取得新凭据。授权接纳在外部请求之前结束：撤销阻止后续接纳，不能撤回已发出的请求。

通过 `postgres.Migrate` 显式初始化 schema，迁移在事务中串行执行并校验摘要；未知或被修改的版本直接失败，不静默修复。`tests/e2e` 的数据库集成测试使用 `postgres` build tag，要求 `JUEX_TEST_POSTGRES_URL` 指向有建库权限的临时测试服务器。每个用例创建和删除独立数据库。CI 使用 PostgreSQL 18 执行这些用例。

持久站内通知归每个租户中的资源所有者。只有该登录用户能读取、修改已读状态和投递偏好；
Fleet 代管权限不授予个人通知权限。应用、Fleet 与事件身份对不可变载荷去重。
完成通知需主动开启，提醒与需要处理的事件默认显示；偏好影响之后产生的通知。
每次业务邮件发送前核对当前成员状态、已验证的当前邮箱及投递偏好。邮件只含需登录的
站内通知链接，不携带应用证据或对话内容。SMTP 重试保留消息身份，但不能保证远端恰好一次投递。

永久清理以持久任务处理归档 Agent 或已移除成员的 Fleet。Management 固定目标身份，先让所有服务阻止新工作，再逐项清理，并分别确认和重试。服务保留清理标记，拒绝迟到写入和旧资源重建。平台数据清理与外部操作停止核验分别展示。用量和审计保留；Fleet 清理后，原用户重新接受邀请才创建新 Fleet。历史备份按部署方保留策略过期。
