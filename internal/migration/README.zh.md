# 离线迁移

> [English](README.md) | 中文

`legacy` 读取固定的 `281889e5` Fleet、Agent、Thread 和 Memory 格式，不打开
具有恢复写入行为的旧存储。它保留原始文件字节、按序历史事实、当前 Generation
的完整上下文、终态 Input、Memory 知识/回执/删除约束，以及模块和扩展的私有文件，
不访问数据库、服务、模型或工具。

读取成功表示批次、游标、身份、用量和源文件稳定性检查通过，不表示运行中的
Fleet 已经静止。合法空输入队列的文件缺席也会记录，并在捕获结束前再次检查。
未完成批次、未知事实、未结算输入、有歧义的 Thread 名称、不一致投影，以及未完成
的 Memory/配置事务会被拒绝，不会修复源文件。
即使最后一次 Turn 失败，Worker 的保留状态仍以归档、恢复的 metadata 为准。
Memory 禁存范围保留原始作用域，包括跨 Generation 的范围。

`EncodeCapture` 输出固定版本的私有 Fleet 快照；`DecodeCapture` 要求提供独立记录的
SHA-256，不重新打开源路径。原始字节去重不会合并所有权或缺席记录。Thread 坐标、
续接上下文和 Memory 投影会从原始字节重建并校验。报告 JSON 不是快照格式。快照
包含私有历史和配置；启动/认证证据、选中的扩展安装和目标绑定仍需由操作工具的
外层迁移包一起固定。

App 的 `WriteBundle` 用三个文件固定该快照、私有配置/认证/资源证据、明确的目标
策略与目标身份。`LoadBundle` 要求独立保存的 manifest 摘要和目标身份，拒绝被修改、
缺失、非私有或符号链接的文件。文件原文和环境值的未知/缺席/空值状态在往返中保留。
纯 `Prepare` 不重新打开源路径、不分配目标 UUID，解析模型目录与初始 Agent/资源
策略。这不证明源已停止，不授权数据库写入、不安装资源或激活 Agent；仍需执行
各服务负责的导入与真实行为验收。
已启用的源 Agent 必须明确选择目标按需激活策略；旧进程的 autostart 值保留在快照中，
共享 Runtime 不复刻每 Agent 的登录启动任务。禁用的源 Agent 需要另行转换。

`SourceGuard` 只打开固定源版本已有的写入锁，并持有到导入结束。锁缺失或忙碌、
目录被替换、Agent 注册集合变化都会停止操作；它不创建或修复源文件。捕获复用
已打开的根目录句柄。`VerifySource` 对比完整捕获与冻结迁移包，不因不一致而刷新
迁移身份。这些锁不覆盖旧 Fleet HTTP 的恢复接口和外部编辑器：操作人员必须在
捕获和切换前独立停止源服务及子进程、禁用自动启动，并保留已验证的备份。

仅随平台发布的 `juex-migrate apply` 读取现有私有 Host 部署，要求继承操作工具已持有
的维护排他锁描述符。已有存储目录必须保持私有权限和目录身份；未完成安装、恢复或
权限复核时拒绝导入。它拒绝环境中的 `PG*` 连接设置，使用部署的 Unix socket 数据库
及固定端口 5432、保持单连接、检查离线清单，
通过 Management、Execution、Runtime、Memory 和 Calendar 各自的接口导入。只有全部
未完成上传都匹配本迁移包、真实目标 Agent、当前权限和完整请求时才恢复；其他未结束
工作会阻止导入。精确重试复用各服务回执；失败保留部分提交与维护状态。普通备份和
升级的就绪条件不变；迁移重试必须先独立确认写入服务和 executor 仍已停止、PostgreSQL
仍可用，再进入该 helper。

Apply 不选择默认执行环境、不安装或连接扩展、不恢复平台运行。这些步骤及应用行为
验收仍须完成。捕获的 Calendar 状态要求源端已选择 Calendar MCP 扩展；残留文件不能
授权重新启用旧日程。

Agent 捕获包括被引用的媒体和 spool 文件内容，并验证其 hash。Fleet 捕获要求明确
提供源用户的默认 Home，保留配置层和导入缓存字节，并记录配置缺席。对于外部
Workspace，捕获配置、`.env`、`AGENTS.md` 和 `.agents/AGENTS.md` 的原始字节或缺席记录，
不接管其所有权，也不复制其中的任意文件。保留配置或扩展
私有文件并不表示已经完成行为转换。用户切换前，完整迁移仍需通过可校验备份、
各服务所属的导入流程和行为验收。

`ReadExtension` 独立于 Fleet 状态捕获明确选中的安装目录。调用方证明 allow 策略和
优先级胜出的根目录；reader 不合并扩展，也不执行代码。它保留 manifest 和已启用
资源入口的字节、hash 与缺席记录，不探测禁用类别。脚本和任意辅助文件仍需由
单独的备份保留。符号链接安装或选中资源需要另行证明处理方式，因此会被拒绝。
这种捕获不会创建目标扩展授权，也不证明命令、环境或私有状态已经兼容。

`ConvertStdioExtension` 把选中的 v1 stdio 声明转换为现有 v2 manifest。显式可执行文件、
进程 cwd 和 Runtime WorkDir 绑定通过固定 argv launcher 保留源端不同的位置。
扩展私有路径仍由 Execution 所有。未支持的 transport、Agent 级默认环境、缺少资源
不存在的证据、Shell 自管环境值及未解决的参数路径，需要单独转换。转换不安装依赖、复制私有状态、
连接 MCP 或订阅通知；这些仍需安装流程和行为验收。

`internal/app/migration.ResolveConfig` 按固定源版本的合并规则解析已捕获的 Home、
Workspace、Agent 和显式启动文件层。远程导入必须匹配源地址、声明文件和启动上下文
的精确缓存身份；转换不请求网络，也不重新发布配置。报告不包含 provider 的私有值。
结果描述磁盘配置，不证明继承环境、认证信息或目标资源绑定。未支持的字段、缺失或
相互矛盾的捕获证据会明确阻止解析。

随后 `ResolveModels` 应用明确提供的源有效环境和捕获的 Codex 凭据。未知环境值与
缺席、空值不同；私有 profile 不进入 JSON 报告。它保留 fallback 选择和请求时身份
模板，不读取导入进程的环境，也不刷新 token。调用方仍需证明进程与认证捕获的出处
以及 provider 可用性。发布模型目录前，还需协调源输出上限、目标预算预留和
Management 账户绑定；源解析成功本身不代表已得到可部署的目标配置。

`ConvertModels` 从已解析 profile 和显式预算预留生成私有发布计划。只有全部私有
设置相同，才合并有效 provider/model 身份。共享主模型必须有一致的有序、直接
fallback 链，包括显式空链。保留源请求上限和有效能力；隐式 endpoint 必须先完成
解析。计划的 JSON 不包含密钥，也不授予覆盖现有目录项的权限。`PublishModels` 通过
适配器校验及 Management 的离线原子导入，初始化空部署模型目录和未设置的租户模型
策略。它写入直接 fallback 链与目录 allowlist，保持平台默认模型不变；精确重试返回
稳定 UUID，不恢复运维方后续修改。来源证据和 Agent 绑定仍由调用方负责。

`ConvertAgentConfig` 在安装资源之前准备新 Agent 的初始配置，不用于更新补丁。
它把已解析模块映射到现有能力分组，要求显式模型、静态指令、Files、Shell、Calendar
和协作绑定。源文件与搜索开关不等同于目标的工具分组；即使旧 Shell 模块关闭，源
Hook 和命令 Observable 在目标也要求 Shell。未解决的组合会被拒绝。
旧 Supervisor 管理权限不代表跨 Agent 消息权限。动态指导依赖目标 Files；全局指导
还要求源用户资源策略开启，并绑定所选 Execution 环境上的路径。Workspace、生命周期、
Memory profile、skill 选择及资源内容仍需分别转换。

Management 的离线 `ImportAgents` 原子保存初始定义及源 ID 映射。匹配的重试返回相同
目标身份；名称不是迁移键。它要求固定预期的新 Fleet，并拒绝在清理后重建。此回执
不授权后续服务导入，也不证明源状态、资源和生命周期已完成迁移。

消息与终态输入的纯转换位于 `internal/app/migration`，在这里组合服务的类型契约和
固定源格式 reader。消息身份限定在目标 Agent 与 Thread 内。spool 引用恢复为经过
校验的完整正文；图片引用要求匹配的 Execution 私有 Artifact 回执。仅在逐字重建
并证明源后缀后，才改写自动生成的压缩引用，保留模型撰写的正文。源输入处于 settled
不代表成功；对应的持久终态事件区分完成、取消和失败。转换不执行 I/O 或重放工作。

Runtime 转换保留不可执行的源 Commit/Input 记录、规范消息和明确的继续执行检查点。
只有旧版对模型可见的消息进入检查点；仅供展示的策略消息及被拒内容仍保留为可读
历史。身份映射和 Commit 的事件闭区间支持后续证据范围转换。消息副本冲突或引用
无法解析时拒绝转换。经过验证的源 Memory assignment 文件保留 Worker 用途和不可执行
的审核关联，不复制凭据。多个历史 Worker 可以对应同一业务审核；转换不会编造任务或
合并它们的结果。其他应用任务关联及模型来源要求明确且已验证的绑定。当前压缩
metadata 若包含没有可用模型读取路径的图片，也会被拒绝。

Memory 转换使用同批 Runtime 身份和完整 Commit 区间，映射条目与事实的出处、审核
证据、来源游标和禁存范围。终态结果和知识版本保持不变；旧 assignment 凭据不会变成
当前权限。待处理历史证据由 Memory 保留为不可执行的历史，包括当前 Advanced 协议
不再收集的助手证据。来源退出设置在配置变更后仍然生效。所有权、历史或范围边界无法
映射时拒绝转换。原始源字节保留旧调度和召回统计，不将其变成活跃任务，也不据此宣称
新的处理成功。

Calendar 转换读取捕获的 v1 扩展数据，要求显式的同所有者 Agent 映射及固定捕获时间。
它保留规则时钟和下一触发时刻，将源 catch-up 默认值映射为 none；可选名称为空时
使用源 ID。Calendar 建立新版本和授权 epoch，源数据不能提供活动投递回执。
待发送事件、附件、发送历史、调度错误及 interval 锚点重设需要单独证明转换语义，
当前明确拒绝。已跳过且没有未来时刻的一次性规则保持完成。旧扩展不能与新的
Calendar 所有者同时运行。
