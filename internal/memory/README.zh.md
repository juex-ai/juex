# Fleet Memory

> [English](README.md) | 中文

Memory 在独立 PostgreSQL schema 中拥有共享知识和审查收据。
`juex-memory` 提供双向认证的 Kitex RPC，由 Management 解析当前 Fleet 或
Agent 权限。执行设备不能访问 Memory 服务。出处引用表示来源，不授予读取其他
Agent 对话历史的权限。

应用开关和执行代际属于 Memory。停用阻止 Agent 读取、新提案和审查提交；有权限的
用户仍可只读查看。启用或切换策略会推进代际，不能复活旧任务。提案收据只确认接收；
只有已提交的审查决定才确认知识变更。

存储层在一个事务内串行修改每个 Fleet 的有界状态。知识校验包含全部条目，防止不同
条目的冲突事实通过并发提交。版本、知识变更、决定收据、用户控制代际和来源抑制
原子保存。重复提交已完成的决定只返回原收据，不重新应用其变更。

Agents 共享适用的 Fleet 知识；适用范围筛选不授予访问权限。搜索返回有界预览；显式
读取条目包含来源元数据。时间查询保留当前、历史和指定时点的语义，包括不确定日期和
已纠正断言。用户纠正、删除和禁止存储会撤销待处理审查。遗忘清理 Memory 拥有的证据，
并阻止从这些来源重新抽取，包括换用其他条目 ID。原始对话历史属于 Runtime。
显式重新学习只移除选定的约束。

审查绑定和原始证据经可信 Runtime 组合层传入，不接收模型伪造的角色或能力字段。
Runtime 拥有普通 Worker 执行、模型凭据和用量；Memory 拥有应用层提交决定。

Memory 审查在 Worker 任务中固定独立的上下文与输出预算。Runtime 将它与每个授权模型
的限制取交集，跨回退、工具轮次和重启保留；普通 Agent 模型策略不受影响。

审查投递记录以稳定审查 ID 接纳一个普通 Runtime Worker，能恢复丢失的接纳回复，
也能在接纳前取消已撤销任务。Worker 具有持久模型调用预算，且只能使用知识审查工具。
成功决定后允许生成最后回复，但不能再次修改知识。Runtime 从当前输入注入有界原始
用户证据；其他 Agent、应用和观察消息不能被冒充为用户陈述。工具命令 ID 在服务重启后
仍能确定取消与接纳的先后；停止来源对话不会撤回已经接纳的审查。

Management 将已认证的人类操作转发给本服务：知识、审查收据、存储限制及带版本的应用
配置。停用后这些视图仍可读取；Runtime 调用方不能使用人类管理操作。校验回复只暴露
有界的业务原因，使审核 Worker 能修正提案，同时不泄露内部诊断信息。

Advanced 持久保存参与边界，不依赖进程心跳。Runtime 在 Turn 完成后通过有序投递记录
发布原始直接用户输入，其他输入类型不会成为证据。启用、切换策略和显式人类管理操作
都会建立新的输入接收时间边界，断线期间积压的旧投递不能回填。

自动审核在五个已完成用户 Turn 或低流量持续 24 小时后，冻结最多 100 个事件、32 KiB
证据。显式维护和缓冲压力可绕过数量与等待门槛；接纳仍要求来源 Thread 空闲 60 秒、没有
待处理或 held 输入、没有不确定工具操作。Runtime 按 Fleet 串行接纳自动 Memory 审核，
繁忙来源不会阻塞其他符合条件的来源。重试恢复同一个 Worker；失败范围保留结论，不会
被后续输入偷偷重新打包。终态审核的原始证据在七天后清理，收据身份和共享知识出处保留。

Advanced 对每个原始人类输入准备一次有界的关键词检索快照。Runtime 连不可用结果也会
持久保存，因此恢复、重试和工具迭代都不会重复检索。注入时核对当前应用代际与人类管理
屏障，并检查所选模型的上下文容量；快照只作可选参考，不进入持久对话历史及压缩摘要。
Memory 服务暂时不可用不会阻塞普通对话。

业务决定在同一事务内固定结果通知。Runtime Main 与 Management 站内通知分别确认投递，
各自有界重试。通知只包含结果摘要，不携带原始证据或模型编写的原因。知识提交之后的
Worker 收尾失败不能改变业务结论；通知暂时不可用不阻塞审核处理。

Agent 清理会删除其私有审查证据、参与状态和待处理命令，保留 Fleet 共享知识。整个 Fleet 清理则删除应用状态。持久清理标记与初始化、修改共用 Fleet 事务锁，防止迟到调用重建已删除状态。
