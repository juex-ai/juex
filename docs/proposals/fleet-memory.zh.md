# Fleet Memory 完整方案提案

> [English](fleet-memory.md) | 中文

状态：完整设计评审草案，尚未按本文实现。更新：2026-09-17。

依赖 [Fleet 服务管理与接入](fleet-service-management.zh.md)。Memory 运行在独立服务进程，改变知识的模型工作由 [Supervisor 角色](supervisor-agent.zh.md) 执行。Memory Service 拥有数据、请求、策略和提交，Supervisor 拥有推理执行，Fleet 管理进程负责服务管理与发现。三份提案中，本文是 Memory 设计的权威文档。

当前 [Memory 实现](../../internal/features/memory/README.zh.md) 保存 Agent 范围的知识并提供直接写入/删除工具。本文改变这一边界，交付之前当前实现文档继续有效。

## 产品契约与策略

一个用户/Fleet 拥有共享记忆。普通 Agent 查询并提交更新请求，Supervisor 通过 Memory 服务提交模型提出的新增、纠错、合并或删除，不直接编辑共享文件。首版由配置的 `agent`/`supervisor` profile 区分操作能力，完整身份认证后续实现。索引、访问元数据、请求状态等机械性数据由服务代码维护，无需模型决定。

一个 Memory Feature 同时只运行 `basic`、`advanced` 中的一种策略。Advanced 复用 Basic 的数据和工具并增加自动工作，不是并行运行的第二份记忆库。

| 能力 | Basic | Advanced |
| --- | --- | --- |
| 有界搜索、条目读取、获准的历史检索 | 参与 Agent 可用 | 相同 |
| 更新提案和结果查询 | 参与 Agent 可用 | 相同 |
| 知识评审和提交 | Supervisor 处理已提交请求 | 相同 |
| 校验、并发、保留、LRU、持久请求状态 | 服务代码保证 | 相同 |
| Turn 准备时自动召回 | 无 | Harness 准备有界召回 |
| 空闲历史自动提取 | 无 | Memory Service 生成任务，由 Supervisor 领取执行 |
| 结构化实体、事实、关系和时间检索 | 已有数据保留，不执行依赖图谱的行为 | 启用 |

Basic 仍由模型主动发起：用户或 Agent 决定查询或提出更新。Supervisor 处理显式请求属于 Basic，会消耗模型额度。Advanced 额外在没有显式 Memory 工具调用时主动召回和维护。两种策略都不保证每段对话必然产生有价值的记忆。

示意配置，具体字段待实施评审：

```yaml
fleet:
  services:
    memory:
      mode: managed
      enabled: true
      config:
        strategy: basic     # basic | advanced

modules:
  memory:
    enabled: true           # 当前 Agent 参与
    service: memory
    profile: agent          # Supervisor 使用 supervisor
```

建议新启用 Fleet Memory 时选择 `basic`。除非另行修改，Agent 沿用当前预设参与默认值：`standard` 开、`minimal` 关。Fleet 配置管理服务启用及服务级策略，由 Memory Service 执行；Agent 控制自身参与和能力配置，不能覆盖共享策略。服务就绪且允许参与才能使用；自动维护还需要可用的 Supervisor 执行者及获准工具。

## 所有权与组件

| 组件 | 职责 |
| --- | --- |
| 独立 Memory Service | 共享存储、查询/提交操作、请求记录、维护调度、进度和删除约束。 |
| Agent Memory Module | 工具、必要指导、可选 Turn 召回，以及经类型化 MemoryClient 贡献来源材料。 |
| Supervisor Memory Worker | 评估提案、读取允许的证据、提取候选、处理冲突并提交类型化决策。 |
| Thread/EventStore | 原始对话及事件顺序的权威，通过现有有界操作访问。 |

默认每个 Fleet 启动一个 Memory Service，拥有自己的 RPC 监听器、私有存储和恢复流程。Fleet 管理它的进程和 endpoint，不代理查询、不持有 Memory 队列或运行 Provider。存储与查询就绪不依赖 Supervisor 在线；管理进程重启不停止 Memory，具体生命周期遵循基础提案。

Juex 默认使用内置 Agent Memory Module 加同一份类型化 MemoryClient；普通 Agent 和 Supervisor 仅在 profile、注册工具和执行用途上不同。Module 不保存权威知识，关闭某个 Agent 的 Module 只停止它的参与和客户端资源。

需要外部 Agent 接入时，可增加同一服务的 Streamable HTTP MCP 适配；需要 stdio 时，只增加连接此服务的轻量桥接进程，不为每个 Agent 启动独立记忆库。首版交付内置 Module/RPC，不同时建设全部适配。HTTP MCP 的工具入口本身不替代 Juex 的 Turn 召回集成。

服务可采用内置启动命令或独立二进制，属于部署选择，不改变进程边界。客户端用所属 Fleet 的 resolver 发现 `memory`，直接连接服务；不存在公共 Fleet Client Module 或 Fleet Module Host 依赖。

## 三层存储

提议 Fleet 布局：

```text
$JUEX_HOME/services/memory/
  MEMORY.md                  # 自动生成的热点索引，最多 200 条
  memory/<id>.md             # 权威知识条目与元数据
  index.sqlite              # 可重建的全文/实体/关系投影
  state/                    # 权威请求、回执、进度、
                            # 提交意图和抑制约束

$JUEX_HOME/agents/<agent-id>/threads/.../generations/*.jsonl
                            # 原始历史继续归 Thread
```

面向用户的三层是热点索引、详细条目、原始历史。操作状态独立存储，不能从搜索索引重建。所选检索/图谱实现需要时才创建 SQLite 投影。`state/` 内的准确文件格式属于实施选择，下述持久语义必须满足。

条目具有稳定 ID、简短名称/摘要、知识版本、正文/类型、适用范围、来源引用和创建/更新/访问元数据。共享所有权不使每条事实全局生效，用户偏好、项目约定和特定 Workspace 的事实保留各自范围。

`MEMORY.md` 由代码生成，模型提出条目正文和摘要，不手工编辑生成索引。搜索覆盖全部获准条目，包括已退出热点索引的条目。空查询和历史读取都分页、有界。

历史引用包含 `fleet_id`、`agent_id`、`thread_id`、`generation_id` 和事件序号/范围。Memory 经窄 Agent 历史接口使用 Thread/EventStore，不自行 glob 文件；来源 Agent 可以贡献有界快照或引用。归档移动不改变身份，已删除或不可访问的证据明确报告不可用。普通 Agent 只获得当前工作范围内的历史操作，不自动获得全部 Agent 对话。首版来源身份属于可信调用上下文声明，不宣称已经过密码学验证。

## 索引、LRU 与检索

Memory Service 协调本 Fleet 唯一的热点索引：

- 新条目进入热点索引；显式成功读取正文刷新访问时间，冷条目可重新进入。
- 搜索预览、列目录、重建索引和维护读取不刷新 LRU。标明执行用途，避免维护 Worker 无意中把所有条目变热。
- 超过 200 条时，按最近显式访问时间淘汰最旧索引项，同值时采用确定性次序；保留条目文件和证据。
- 自动注入单独记录使用情况，不自动刷新 LRU，避免排名自我强化。
- 索引摘要和查询/召回结果另设大小预算，200 条不是 prompt 预算。

访问记录由服务维护，不是知识变更，不应使 Supervisor 的预期知识版本失效。派生索引失败可观察、可修复，不能删除已提交条目，也不能让冷条目永久无法搜索。

Basic 可以从名称、摘要和正文的词法检索开始。Advanced 增加结构化过滤和排序，交付 Basic 不要求先选择更复杂的检索后端。

## 工具、指导与请求流程

建议操作如下，最终工具名和模式待评审：

| 调用者 | 操作 |
| --- | --- |
| 参与的普通 Agent | 搜索/读取记忆、查询允许的历史、提出更新、查询自身请求结果。 |
| 限定能力的 Supervisor Worker | 上述操作，加证据评审、提交变更、拒绝请求、以无有用变更完成维护。 |
| 可信用户管理入口 | 经服务显式纠错/删除、控制不存储；模型不能自行授予此权限。 |

所有模型知识变更经过 Supervisor。客户端启动配置选择 profile，模型工具参数不能自行切换。服务端检查 profile 允许的操作、当前分派、来源范围、预期版本和删除约束；仅隐藏普通 Agent 的提交工具不够。身份认证暂缓不代表省略业务校验；profile 和租约不构成防止恶意客户端冒充的认证方案。在目标设计中，普通直接写入/删除工具被提案操作替代，不能保留直接写入的误导描述却只排队请求。

Memory 提供自己的简短指导和内置指南，说明条目质量、逐层查询、LRU、证据和请求回执。Skills 可提供完整指南，但关闭 Skills、外置 Hooks、MCP、Extensions 不影响 Memory 的必要指导和代码内集成。

```text
Agent 提交变更建议、原因和有界来源引用
  → Memory 校验能力配置和来源范围并持久保存请求
  → 返回接收标识
  → Supervisor 经同一 MemoryClient 领取有界分派并评审证据
  → 提交类型化变更、拒绝或无变更结果
  → Memory 校验、提交并发布结果
```

请求状态区分 `pending`、`running`、`applied`、`no_change`、`rejected`、`failed`。基础设施失败的尝试可按重试策略返回 pending，最终失败明确记录。响应与状态说明是等待 Supervisor、重试中，还是需要用户补充。

来源 Agent 可以在期限内等待或稍后查询。收到回执后只能说“已提交记忆更新”，知识提交完成后才能说“已经记住/更新”。明确“记住这个”的请求不等待自动提取阈值，但仍经过相同评审和提交流程。领取与提交采用短 RPC，模型推理期间不保持同步业务调用；客户端超时不撤销已接收工作。

## 提交、并发与恢复

一个 Fleet Memory 服务协调写入，推理期间不持有存储锁。知识提交比较条目预期版本，应用有界变更集。过期工作必须重新读取并处理冲突，不能覆盖后来的纠错。

持久请求 ID 标识工作，同一幂等键携带不同内容必须拒绝。分派尝试具有租约/隔离令牌；服务恢复时核对持久尝试状态，过期、取消或重新分派后的旧令牌不能提交。Supervisor 替换需通知 Memory 使旧分派失效，未确认前不宣称已撤销。重复推理可能消耗额度，但相同已接收结果不能重复修改知识。

服务先记录可恢复的提交意图，再发布变更集，随后提交结果回执及来源进度。读取者看到已提交视图，不观察到多条目合并的一半。在条目发布与回执发布之间崩溃时，先依据操作 ID 和意图恢复，再接纳冲突写入。持久细节归 Memory，不扩展成跨服务事务框架。

权威知识先于派生索引提交。回执区分知识已提交与索引就绪；修复失败不能把成功的知识提交描述成未发生，恢复时修补投影。`no_change` 是成功处理结果，应推进对应维护进度；操作故障不能悄悄推进进度。

Supervisor 拒绝是业务结果，不是传输失败。当前明确用户纠错优先于旧推断，并按需保留来源和时间。旧更新的重试不能撤销后续删除或用户新纠错。

## Advanced 历史维护

Memory Service 从参与的来源 Thread 选择有界、已提交、未处理的历史，创建供 Supervisor 领取的提取和整理任务。统一提交协调者避免不同 Agent 各自维护同一份知识；Fleet 管理进程不负责这些业务调度。

原始需求是在 Thread 空闲且产生五个 Generation 后触发。本文暂保留该单位供评审：五个已结束且未处理的上下文 Generation，加空闲窗口和无待处理 Input。Generation 不等于 Turn，可能包含许多 Turn。此前建议过改为已完成 Turn/内容量阈值，但尚未确认。空闲时长、最大等待时间和批次预算仍是可调评审项。

无论选择哪种触发，处理进度使用 Thread 连续的已提交事件序号，不使用目录数量或文件修改时间。分派时冻结来源上界，后续对话不扩展该批次。低频 Thread 需要最大等待或手动整理入口，显式更新不等待自动阈值。

处理流程：

1. 冻结符合条件的来源范围和排除元数据。
2. 在有界 Supervisor 分派中提取带直接证据的候选。
3. 对照当前条目，提出新增、纠错、合并、失效或无变更。
4. 通过与 Basic 相同的服务操作校验并提交。
5. 记录持久结果，只推进实际覆盖的来源范围。

排除 Memory 维护 Thread 自身、召回注入和生成摘要作为独立事实证据。事实需要原始来源，模型重复不构成佐证。持久保存退出参与和不存储的边界，恢复后不能回填被排除内容。任务进度归 Memory，不由执行 Thread 的完成标记决定。

限制后台并发、重试退避和模型额度，避免长维护队列阻塞显式纠错。通知可以唤醒调度，持久进度与核对负责发现遗漏。维护失败不能把已完成的用户 Turn 改为失败。

## Advanced Turn 召回

输入接纳后、Turn 首次 Provider 请求之前，Agent Memory Module 使用已接纳输入、当前 Agent/Thread 范围，以及解析“那个项目”等指代所需的有限上下文，通过 MemoryClient 从 Memory Service 获取有界召回快照。在当前准备边界冻结结果，不在每个工具迭代或状态检查时重新检索。运行中的 Turn 新接纳输入时，可以有单独标识的有界准备。

召回先过滤范围和删除约束，再检索条目/事实、排序去重，以带来源和时间的历史上下文贡献。允许结果为空。当前用户指令和纠错优先，召回材料不成为更高优先级指令。

现有 `ContextRequest` 缺少 Turn ID 和已接纳输入。如有需要，增加带取消、结果身份和预算的窄通用准备契约，Memory 拥有检索语义。不在被动检查也会调用的 context 方法中做有副作用召回，不改写用户原文，不依赖外置命令 Hook。

召回有期限和上下文预算。Memory Service 不可达时产生可观察的不可用结果，Agent 普通执行继续；显式工具仍返回错误，不伪造成功。仅 Fleet 管理进程不可用，不应中断已连接的 Memory 查询。断连时不把缓存 Memory 快照作为新召回注入。先前注入的历史文字不等于实时权威副本；获知适用的删除/禁记约束后，在下一个安全准备边界使活动召回失效。离线 Agent 不能承诺立即获知新约束。

## 结构化知识与图谱

Advanced 使用统一实体/事实/关系模型，再提供领域视图，不建立相互冲突的独立图谱：

| 视图 | 示例 |
| --- | --- |
| 用户档案/偏好 | 明确姓名、出生信息、居住地、偏好、自述 MBTI。 |
| 社交/组织 | 人物、组织、家庭、朋友、任职和合作关系。 |
| 工作/项目 | 项目成员、职责、技术环境、长期决策。 |
| 生活/事件 | 地点、迁居、学习和具有生效时间的事件。 |

事实记录主体、属性/关系、值、范围、原始来源及类型、记录/生效时间，以及有效/已替代/有争议状态。条目的结构化元数据是权威，SQLite 图谱/检索表是可重建投影。操作方法和解释继续适合 Markdown。

不为填满图谱而推断敏感档案。MBTI 是有时间依据的自述；由生日计算星座时标明派生。仅姓名相同不足以确定实体相同。冲突保留不确定性；从上海迁居杭州更新当前居住地，并保留有依据的历史有效期。图谱推断不能暗中覆盖明确用户纠错。

## 保留、删除与策略切换

| 操作 | 语义 |
| --- | --- |
| 热点索引淘汰 | 保留条目及可搜索性。 |
| 纠错/合并 | 提交新知识版本，保留适当来源和时间语义。 |
| 删除记忆 | 删除知识及派生投影，阻止旧写入，并抑制从被删除来源再次提取。 |
| 删除来源 Thread | Thread 拥有历史删除；记忆不自动删除，证据缺失可见。 |
| 本输入不要存储 | 在提取使用之前持久保存排除，不删除无关知识。 |
| Agent 退出参与 | 停止其工具、召回和新贡献，保留 Fleet 数据。 |
| 停止受管 Memory Service | 结算在途操作，停止接入，保留知识和已接收任务；不等同于停止 Fleet 管理。 |
| 禁用 Fleet Memory | 停止接入和受管服务并禁止自动启动；external 只禁用 Juex 接入，保留数据。 |
| Advanced → Basic | 停止自动召回/提取，保留数据和结构化元数据，继续处理显式请求。 |
| Basic → Advanced | 校验/重建投影，仅恢复符合条件的来源范围。 |

删除先提交抑制约束，使旧 Worker 无法重新发布内容。在 Memory 所有权内处理条目、索引、请求正文/候选快照和待执行工作。只保留防止复活所需的最小无正文标记。用户可显式授权重新学习某事实，普通重试不能清除约束。

“遗忘”必须说明范围：删除 Memory 不删除原始 Thread Journal 或 Memory 之外的副本。完整用户数据清除需要分别处理这些所有者，不能只删 Markdown 文件就承诺彻底清除。Agent 收到删除后，已生成的活动召回应在下一个安全边界失效，过去的 Provider 请求或历史对话无法被追溯撤回。

Agent 退出参与时记录来源边界，重新参与后不自动回填退出期间内容。此前已接收的显式更新请求保留可见，直到结算或显式取消；禁用调用者不隐式撤销已接收工作。禁用策略使旧自动分派失效，保留持久进度，阻止按旧策略提交。

## 故障矩阵与交付

| 故障 | 必须结果 |
| --- | --- |
| 提交前 Memory Service 离线 | 不宣称已接收，明确不可用。 |
| Fleet 管理离线而 Memory 仍运行 | 已发现的直接连接继续查询/提交；新启动和管理可能不可用。 |
| 接收/提交后响应丢失 | 查询或重试同一请求身份，不重复效果。 |
| Supervisor 离线 | 查询继续，已接收变更等待。 |
| 条目冲突或分派过期 | 拒绝本次尝试，重新评估当前状态。 |
| 派生索引失败 | 保留已提交知识，报告投影降级，修复时不丢冷条目。 |
| 来源历史不可用 | 报告证据缺失，不编造，也不暗中标记未处理历史完成。 |
| Memory Service 失败 | 其他服务和 Agent 本地功能继续，恢复后核对持久任务和回执。 |

在 Fleet 服务管理/发现和 Supervisor 执行契约之上交付：

1. 独立服务加内置 Agent Module/MemoryClient，完成 Basic 共享存储、有界工具、持久提案、profile 评审/提交、历史引用及 200 条索引。
2. 可恢复 Advanced 提取和有界 Turn 召回。
3. 有限结构化领域视图、时间事实和派生投影。

验收覆盖两个 Agent 共享已提交知识、同机两个 Fleet 不串库、普通 profile 直接提交被拒绝、Supervisor profile 评审提交、提交请求与完成的区别、响应丢失后的重试、旧 Worker 隔离、第 201 条仍可搜索、冷条目重新进入、维护不影响 LRU、无变更推进进度、提交中断恢复、删除不复活、来源退出参与、策略切换、Fleet 管理重启时 Memory 继续工作，以及 Memory 故障下的有界召回。这些不宣称验证了尚未实现的身份认证。遵循仓库 [验证流程](../../.agents/skills/juex-localtest/SKILL.md)。

目标是从现有 Agent 本地 Memory 清晰切换权威归属。不静默合并旧存储、不保留兼容写工具别名，也不自动导入历史数据。在用户决定处置之前保留旧文件；用户要求的导入应独立评审并经过新权限入口。

本文替代 [Module 开关草案](module-switches.zh.md) 中 Memory 的目标设计假设。交付后再将已实现契约更新到 DOMAIN、ARCHITECTURE 和 Memory README。仍需评审 Generation/Turn 触发单位、操作/召回预算、准确条目/图谱模式及用户显式删除控制；所有权和 Supervisor 提交方向已作为共同基线。
